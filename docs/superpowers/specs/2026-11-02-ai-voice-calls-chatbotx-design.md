# Голосовой ИИ-бот GKamion и ChatbotX — дизайн

Дата: 2026-11-02
Ветка: `feature/ru-channels-max-zzap-drom`
Статус: согласовано с владельцем, правки по аудиту внесены, ожидает вычитки

## 1. Цель и контекст

В `/GKamion/AI-phone-bot` работает продовый стек исходящих звонков GKamion:
Asterisk + AudioSocket + Novofon, свои STT/TTS/LLM, сценарии по статусам заказа
(13 «Ожидает оплаты», 16 «Поступил в пункт выдачи», 22 «Самовывоз → Просрочено»)
и робот-оповещения `informerCall` по остальным статусам. n8n запускает звонки по
событиям GKamion, диалоги ведут агенты `lib/voice-*-agent.js` внутри
`voice-ai/gateway.js`, итог звонка уходит комментарием в заказ GKamion
(`lib/voice-order-comment.js`).

ChatbotX уже знает того же клиента: события заказов приходят через
`external-crm-sync` (`ExternalCustomerIdentity` → `Contact`, `ExternalOrder`,
`ExternalOrderEvent`), а в карточке контакта есть секция заказов
(`contact-orders-section.tsx`).

Нужно связать их так, чтобы ChatbotX был **пультом и памятью**, а бот оставался
**исполнителем**, и чтобы клиент мог в один клик (или одной фразой) отключить
звонки робота себе.

Согласованные с владельцем решения:

1. **ChatbotX владеет решением «звонить сейчас»** (с этапа 2). Окно, дедуп,
   лимит параллельных звонков и очередь переезжают в ChatbotX. n8n остаётся у
   бота транспортом событий GKamion, диалоговые агенты остаются у бота.
2. **Отказ клиента гасит все автоматические звонки бота** — ИИ-диалоги
   (13/16/22) и робот-оповещения `informerCall`. Живой менеджер может звонить
   по-прежнему. Это отдельный флаг, не «не беспокоить вообще».
3. **Флаг ставят: бот (по реплике в разговоре), переписка в чате и менеджер
   вручную.** Автоопределение — основной путь, тумблер — резервный.
4. **Транспорт — pull.** Бот обращается к ChatbotX; ChatbotX не нужно знать
   адрес бота.
5. **Неизвестный номер — не отказ.** Нет контакта — нет и запрета, звонить
   можно. Контакт создаётся позже, когда появляется запись о звонке (§7).
6. **Просьба во время звонка не рвёт трубку.** Разговор доводится до штатного
   конца, флаг ставится сразу, следующих звонков нет.
7. **Внедрение поэтапное** (см. §10), старт в тест-режиме.
8. Отдельный API-скоуп `voiceAgent` (не `ecommerce`: токен управляет звонками,
   а не чтением каталога).

**Не входит:** перенос диалоговой логики (`voice-*-agent.js`), перенос
медиатракта, входящие звонки, звонки от лица живого менеджера, запись
разговора (отдельная задача, см. §11).

## 3. Модель данных

### 3.1 `Contact` — три новые колонки

| Колонка | Тип | Смысл |
|---|---|---|
| `aiCallOptOutAt` | `timestamp` nullable | `null` — звонить можно. Не null — запрет с этого момента |
| `aiCallOptOutSource` | enum `aiCallOptOutSource` nullable | `clientCall` · `clientChat` · `manager` |
| `aiCallOptOutReason` | `text` nullable, ≤500 | Цитата клиента или пометка менеджера |

Почему таймстемп, а не `boolean`: та же модель, что `blockedAt` и
`broadcastSubscribedAt` — один столбец несёт и «флаг», и «когда», и даёт
готовый `buildBooleanFromTimestamp` в фильтре.

Индекс: `Contact_workspace_ai_call_opt_out_idx` on `(workspaceId, aiCallOptOutAt)`
where `aiCallOptOutAt is not null`. Нужен для фильтра «кому не звонить» и для
счётчика в списке.

`aiCallOptOutSource` — новый `pgEnum`, по образцу `whatsappCallOutcome`.
Ставится всегда вместе с `aiCallOptOutAt`.

**Флаг хранится на контакте, а проверяется по телефону.** У одного человека
часто несколько контактов с одним номером — по контакту на канал
(`docs/inbound-webhooks.md`: контакт с тем же телефоном в другом канале
остаётся отдельным). Звонят на номер, поэтому политика (§4) смотрит **все**
контакты workspace с этим номером в E.164: флаг хотя бы на одном — звонить
нельзя. Индекс `idx_contact_workspace_phone_number` для этого уже есть.

Флаг на контакте без телефона (Telegram, MAX) ставится, но звонки не блокирует,
пока номер не появится у этого контакта. Заметка (§3.2) говорит это прямо.

### 3.2 `ContactNote` — без изменений

При каждой установке/снятии флага пишется заметка:

- «Клиент попросил не звонить: «не звоните мне больше» · звонок 02.11 14:32»
- «Клиент попросил не звонить: «…» · чат. У контакта нет телефона — звонки не
  заблокированы, пока номер не появится»
- «Менеджер Анна сняла запрет на звонки робота 03.11 10:05»

Заметка неизменяема, в отличие от полей контакта, и переживает снятие флага.
Текст пишется **на русском для всех workspace** — как тексты передачи менеджеру
в `external-agent` (§ «Known differences»).

### 3.3 `VoiceCall` — журнал звонков (этап 1), очередь (этап 2)

Одна строка на попытку звонка. Форма близка к `WhatsappCall`, но без
`wacid`/WebRTC и без привязки к инбоксу.

| Колонка | Тип | Смысл |
|---|---|---|
| `id`, `workspaceId` | как везде | |
| `phone` | text, not null | Номер в E.164 — по нему идёт проверка запрета |
| `contactId` | FK `Contact` nullable | Связывается, когда контакт известен или создан (§7) |
| `conversationId` | FK nullable | Если у контакта есть диалог — карточка звонка идёт туда |
| `provider` | text, not null | `novofon` |
| `scenario` | text, not null | `prepayment` · `pickupReady` · `pickupOverdue` · `informer` · произвольная строка |
| `status` | enum `voiceCallStatus`, not null | `queued` · `leased` · `dialing` · `answered` · `completed` · `noAnswer` · `voicemail` · `failed` · `canceled` · `suppressed` |
| `externalSessionId` | text nullable | `session_id` бота (`gkamion:prepay:<order>:<ts>`) — ключ идемпотентного создания на этапе 1 |
| `attempt` | integer, default 1 | |
| `scheduledFor` | timestamp, not null | Когда можно набирать (окно клиента уже учтено) |
| `leaseToken` | text nullable | Этап 2 |
| `leaseExpiresAt` | timestamp nullable | Этап 2 |
| `externalCallId` | text nullable | id звонка Novofon |
| `externalOrderId` | text nullable | Какой заказ породил звонок |
| `startedAt`, `endedAt`, `durationSeconds` | | |
| `lastError` | text nullable | |
| `transcript` | text nullable | Полный текст разговора (ПДн, §11) |
| `summary` | text nullable | Итог одной строкой для карточки |
| `messageId` | `bigintAsString` nullable | Карточка-сообщение в диалоге, без FK — как `WhatsappCall.messageId` |
| `suppressedReason` | text nullable | Почему не позвонили (только для `suppressed`) |

`canceled` — звонок стал не нужен (заказ отменён, §7). `suppressed` — звонок
был нужен, но запрещён (`optedOut`, `blocked`).

Индексы:

- уникальный `VoiceCall_workspace_session_uidx` on `(workspaceId, externalSessionId)`
  where `externalSessionId is not null` — повторное создание с тем же
  `session_id` возвращает существующую строку (этап 1);
- `idx_voice_call_contact` on `(contactId, createdAt desc)` — история в карточке;
- `idx_voice_call_phone` on `(workspaceId, phone, createdAt desc)` — история по
  номеру и пурж по номеру;
- этап 2: частичный `idx_voice_call_pick` on `(workspaceId, scheduledFor)`
  where `status = 'queued'` — выбор следующей задачи;
- этап 2: уникальный частичный `idx_voice_call_one_live` on `(workspaceId, phone)`
  where `status in ('leased','dialing','answered')` — не более одного **живого**
  звонка на номер. Несколько `queued` по разным заказам допустимы: второй
  заказ ждёт, пока закончится первый звонок (§6.3), а не падает на вставке.

**`suppressed` — обязателен.** Без него «почему бот не позвонил по заказу 19625?»
не имеет ответа, и менеджер не отличит «ещё не дошло» от «клиент запретил».

## 4. Политика: единственная точка решения

`packages/business/src/voice-agent/policy.ts`:

```ts
type VoiceCallPolicyInput = {
  workspaceId: string
  phone: string
  now?: Date
}
type VoiceCallPolicyResult =
  | { canCall: true; contactIds: string[] }
  | {
      canCall: false
      reason: "optedOut" | "blocked" | "invalidPhone" | "outsideWindow"
      contactId?: string
      optOutAt?: Date
      optOutSource?: AiCallOptOutSource
    }
```

Политика **только читает**: контакты не создаёт, ничего не пишет. Читает
мимо кэша (`contactService.findBy` ходит через `withCache` — свежий запрет не
должен ждать истечения TTL).

Правила в порядке приоритета:

1. Телефон не нормализуется в E.164 (`normalizePhoneToE164`) → `invalidPhone`.
2. Найти все контакты workspace с этим номером.
3. Хотя бы у одного `aiCallOptOutAt` не null → `optedOut` (с `contactId`,
   `optOutAt`, `optOutSource` самого раннего запрета).
4. Хотя бы у одного `blockedAt` не null → `blocked`. Заблокированный контакт не
   получает и звонков — существующая семантика блокировки. При нескольких
   контактах решаем консервативно: блок любого из них гасит звонок.
5. Вне окна 09:00–22:00 по TZ клиента → `outsideWindow` — только когда `now`
   передан явно (планировщик, этап 2). Бот на этапе 0 окно проверяет сам.
6. Иначе `canCall: true` с найденными `contactIds` (пустой массив — номер
   неизвестен, звонить можно).

**Fail closed.** Любая ошибка чтения (БД, таймаут) → звонка нет,
`lastError: "voiceCallPolicyUnavailable"`, запись в `error-log`. Молчание
дешевле звонка тому, кто просил не звонить. Поведение бота при недоступности —
§7.

`resolveVoiceCallPolicy` — единственное место, где решается «можно ли звонить»:
её вызывают эндпоинт проверки (бот), планировщик и переход в `dialing` (§6.3).
Установка флага — отдельный `voiceAgentService.setAiCallOptOut` (§5).

## 5. Установка флага

`voiceAgentService.setAiCallOptOut({ workspaceId, contactId?, phone?, source, reason?, actorUserId? })`
— один вход для всех источников:

| Источник | Путь | `source` |
|---|---|---|
| Реплика в разговоре | бот → `POST /v1/voice-agent/opt-out` | `clientCall` |
| Сообщение в чате | worker, хук на входящее сообщение (детектор ниже) | `clientChat` |
| Менеджер в карточке | server action | `manager` |

Что делает метод (в одной транзакции):

1. Определяет контакты: по `contactId`, иначе все контакты с номером `phone`.
   Номер известен, а контактов нет (звонок на неизвестный номер) — создаёт
   standalone-контакт с этим телефоном без инбокса и диалога, тем же путём,
   что `syncCustomer` для новых клиентов. Иначе запрет негде хранить.
2. `UPDATE Contact SET aiCallOptOutAt = now(), aiCallOptOutSource = ?, aiCallOptOutReason = ? WHERE id IN (?) AND aiCallOptOutAt IS NULL`.

   Условие на `IS NULL` — идемпотентность: повторный вызов из другого источника
   не перезаписывает первую причину.
3. Вставляет `ContactNote` в каждый реально обновлённый контакт.
4. Начиная с этапа 1 переводит звонки по этому номеру в `suppressed`:
   `UPDATE VoiceCall SET status='suppressed', suppressedReason='optedOut' WHERE workspaceId=? AND phone IN (?) AND status IN ('queued','leased')`.
   `leased` тоже гасится: бот получит отказ при переходе в `dialing` (§6.3) и
   не начнёт набор. На этапе 0 таблицы нет, и шаг не нужен: любой набор, в том
   числе из отложенной очереди бота, проходит проверку в момент набора.
5. `emit` инвалидацию кэша контактов.

Плюс обратный метод `clearAiCallOptOut` — только `source: manager`, только с
`actorUserId`, всегда с заметкой. Снимает флаг со всех контактов с этим номером:
иначе снятие на одном контакте ничего не изменит, пока флаг висит на другом.

### Детектор фразы

`packages/business/src/voice-agent/opt-out-detection.ts`, чистая функция
`detectOptOutRequest(text): { matched: true; phrase: string } | { matched: false }`.

Применяется только к **чату**: worker, `messageType: incoming`, только текст
(не вложения), бот и менеджер не считаются. На звонке опт-аут определяет
LLM-агент бота (`voice-llm-agent.js`): у него есть контекст разговора, и он
отправляет `POST /v1/voice-agent/opt-out` сам.

Нормализация: нижний регистр, `ё`→`е`, сжатие пробелов, отбрасывание пунктуации.

Границы слов — через `(?<!\p{L})` и `(?!\p{L})` с флагом `u`. `\b` в JS
не работает для кириллицы. Без границ шаблон `не звони` ловит «курьер не
звонит» и «мне никто не звонил» — жалобы, по сути просьбы позвонить.

Срабатывают только повелительные формы с уточнением:

- `больше не звони(те)?`
- `не звони(те)? (мне )?больше`
- `не звони(те)? мне`
- `хватит (мне )?звонить`
- `(уберите|удалите|исключите) (мой )?номер (из )?(базы|обзвона|списка|рассылки)`
- `не хочу,? чтобы (мне )?звонил(и)?`

Голое «не звоните» флаг **не** ставит: «не звоните, я сам приеду» — про один
заказ, не про звонки вообще.

Отрицательный фильтр (не срабатываем, если в сообщении есть):

- просьба о звонке: «перезвон», «позвоните», «жду звонка», «наберите»;
- отказ про один заказ: «сам приеду», «сам заберу», «сам позвоню», «сам наберу»;
- вопрос-жалоба: «почему», «когда», «кто» рядом с совпадением
  («почему вы не звоните мне»).

Ложные срабатывания всё равно возможны — поэтому цитата в заметке и снятие
менеджером в один клик.

## 6. Публичный API (скоуп `voiceAgent`)

Новый скоуп: `workspaceApiTokenScopes` + запись в
`workspace-token-scopes.ts` (Record-тип сам заставит — как `Record<ChannelType,…>`)
+ `fields.tokenScopes.voiceAgent` во всех 22 файлах локалей.

| Операция | HTTP | Этап | Права | Назначение |
|---|---|---|---|---|
| `voiceAgent.checkPolicy` | `POST /v1/voice-agent/policy/check` | 0 | `read_only` | Тело `{ phone }` → `{ canCall, reason, contactId, optOutAt, optOutSource }` |
| `voiceAgent.optOut` | `POST /v1/voice-agent/opt-out` | 0 | `full` | Бот ставит запрет по реплике: `{ phone, reason, externalSessionId? }` |
| `voiceAgent.createCall` | `POST /v1/voice-agent/calls` | 1 | `full` | Бот сообщает о начатом звонке; идемпотентно по `externalSessionId` |
| `voiceAgent.reportResult` | `POST /v1/voice-agent/calls/{id}/result` | 1 | `full` | Итог звонка |
| `voiceAgent.nextCall` | `POST /v1/voice-agent/calls/lease` | 2 | `full` | Лизинг одной задачи или `204` |
| `voiceAgent.markDialing` | `POST /v1/voice-agent/calls/{id}/dialing` | 2 | `full` | Последняя проверка перед набором, снимает лизинг |
| `voiceAgent.getSettings` / `updateSettings` | `GET/PATCH /v1/voice-agent` | 3 | `read_only` / `full` | `enabled`, `maxConcurrentCalls`, `callWindow`, `scenarios` |

Телефон передаётся только в теле запроса, не в query string: query попадает в
access-логи (по той же причине в репозитории отказались от `?token=`).
`nextCall` — `POST` и требует `full`: он забирает задачу в лизинг, это запись.

### 6.1 `createCall` и `reportResult` (этап 1)

Бот на этапе 1 по-прежнему сам решает, когда звонить. Перед набором (после
`checkPolicy`) он создаёт запись: `{ phone, scenario, externalSessionId,
externalOrderId?, externalCustomerId? }` → строка в статусе `dialing`.

- Контакт: связывается по номеру. Если контактов с номером нет, а
  `externalCustomerId` передан — создаётся через `externalCrmService.syncCustomer`.
  Если номер совпал с несколькими контактами, `contactId` берётся из
  `ExternalCustomerIdentity` по `externalCustomerId`, а если его нет — остаётся
  `null` (история видна по номеру). `syncCustomer` при неоднозначном
  совпадении бросает ошибку, поэтому вызывать его в этом случае нельзя.
- Повтор с тем же `externalSessionId` возвращает существующую строку.

`reportResult`: тело `status`, `durationSeconds`, `transcript`, `summary`,
`externalCallId`, `startedAt`, `endedAt`. Идемпотентность: повтор на уже
терминальной строке возвращает сохранённый результат. На терминальном статусе
создаёт карточку-сообщение в диалоге (`messageId`). Заметку в контакт **не**
пишет — заметки зарезервированы под историю согласий (§3.2); итог живёт в
`VoiceCall.summary`.

Опт-аут во время звонка отправляется отдельным `optOut`, а не полем в
`reportResult`: флаг должен встать сразу, а не после конца разговора.

### 6.2 `nextCall` — лизинг (этап 2)

```sql
UPDATE "VoiceCall" SET status='leased', "leaseToken"=$token, "leaseExpiresAt"=now()+interval '60 seconds'
WHERE id = (
  SELECT id FROM "VoiceCall" v
  WHERE v."workspaceId"=$ws AND v.status='queued' AND v."scheduledFor" <= now()
    AND NOT EXISTS (
      SELECT 1 FROM "VoiceCall" l
      WHERE l."workspaceId"=v."workspaceId" AND l.phone=v.phone
        AND l.status IN ('leased','dialing','answered')
    )
  ORDER BY v."scheduledFor"
  FOR UPDATE SKIP LOCKED
  LIMIT 1
)
RETURNING *;
```

Гонку двух лизингов одного номера ловит `idx_voice_call_one_live`: при
конфликте задача остаётся `queued`, запрос повторяется.

Ответ содержит: `callId`, `leaseToken`, `leaseExpiresAt`, `scenario`, телефон,
имя клиента, `externalOrderId`, снапшот заказа (то, что сейчас собирает
`order-context.js` у бота), и `language`/`voice` если заданы.

Интервал опроса — 5–10 секунд (не больше 12 запросов в минуту на workspace),
что далеко от per-workspace лимита публичного API
(`apps/builder/src/lib/rate-limit/api-rate-limit.ts`).

### 6.3 `markDialing` и свипер (этап 2)

60 секунд лизинга покрывают только промежуток «взял задачу → начал набор».
Разговор длится минуты, поэтому лизинг на разговор не продлевается:

1. Перед набором бот вызывает `markDialing` с `leaseToken`. ChatbotX ещё раз
   прогоняет `resolveVoiceCallPolicy`. Можно звонить — `leased → dialing`,
   лизинг снимается, `200`. Нельзя (или строка уже `suppressed`/`canceled`) —
   `409 { canceled: true, reason }`, бот не набирает.
2. Свипер (`apps/worker/src/schedule/handlers/sweep-voice-calls.ts`, раз в
   минуту, `distributedLock`):
   - `leased` с истёкшим `leaseExpiresAt` → `queued`, `attempt += 1`; после 3
     попыток → `failed`, `lastError: "leaseExpired"`;
   - `dialing`/`answered` без результата дольше 2 часов → `failed`,
     `lastError: "resultLost"`. **Никогда** не возвращается в `queued`: набор
     уже был, повторный звонок посреди разговора недопустим.

## 7. Что происходит в спорных случаях

| Случай | Поведение |
|---|---|
| «Не звоните» **во время** звонка | Агент бота сразу шлёт `optOut` (`clientCall`), разговор доводится до штатного конца, трубка не рвётся. Бот пишет в заказ GKamion комментарий «Бот: клиент попросил не звонить» (`voice-order-comment.js`) — менеджеры работают и в админке GKamion |
| Тот же номер ждёт звонка по другому заказу | Строки `queued`/`leased` → `suppressed` (`suppressedReason: "optedOut"`); `leased` получит `409` на `markDialing` |
| Номер не найден | Звонить можно (`canCall: true`, `contactIds: []`). Контакт появляется при `createCall` (если есть `externalCustomerId`) или при `optOut` |
| Номер у нескольких контактов | Запрет на любом из них гасит звонок (§3.1, §4) |
| Флаг поставлен на контакт без телефона | Флаг стоит, звонки не блокирует; заметка об этом предупреждает |
| Клиент просит «не звонить» на **автоответчик** | Не считается: опт-аут только по реплике живого человека (у бота это различается — `voicemail-detect.js`), и только когда `stt_text` непустой |
| «Не звоните, я сам приеду» | Флаг **не** ставится: это про один заказ. Детектор чата не срабатывает (§5); агент на звонке решает по контексту, при сомнении — не ставит |
| Проверка запрета недоступна / 5xx / таймаут 3 с | **Fail closed**: номер не набирается. Путь `notifyByOrder` откладывает звонок в существующую очередь (`enqueueDeferredCall`, причина `policyUnavailable`, через 15 минут) — звонок не теряется. Прямые пути (тестовый вебхук, ручной скрипт) просто не звонят и пишут ошибку |
| Номер запрещён в момент набора | Набор не выполняется, бот пишет в заказ «Бот: звонок не выполнен — клиент просил не звонить» |
| Менеджер снимает флаг | Разрешено, `source: manager`, заметка с автором; снимается со всех контактов с этим номером |
| Два инстанса бота одновременно (этап 2) | Лизинг с TTL; второй получает `204` |
| Два заказа одного клиента (этап 2) | Обе задачи `queued`; второй звонок выдаётся только после завершения первого (`idx_voice_call_one_live` + `NOT EXISTS` в `nextCall`) |
| Заказ отменён, пока звонок в очереди (этап 2) | `externalCrmService.recordOrderEvent` на терминальный статус заказа переводит `queued`-звонки по этому заказу в `canceled` |
| Workspace заблокирован / триал истёк | Звонить нельзя: `checkPolicy` и `nextCall` отвечают отказом. `withBlockedOwnerGuard` есть только в worker (свипер, хук детектора); для публичных эндпоинтов проверку блокировки владельца нужно добавить явно — уточнить в плане |

## 10. Этапы

### Этап 0 — флаг и проверка в боте (тест-режим)

ChatbotX:

1. Миграция `Contact` + `pgEnum` + индекс (миграцию показать владельцу,
   применять после явного разрешения).
2. `voiceAgentService.setAiCallOptOut` / `clearAiCallOptOut` + заметки.
3. `resolveVoiceCallPolicy` + fail-closed.
4. Скоуп `voiceAgent`, операции `checkPolicy` и `optOut` (+ CLI/MCP).
5. Детектор `detectOptOutRequest` + хук на входящее сообщение в чате.
6. Тумблер в карточке + бейдж + фильтр.

Бот:

7. Новый `lib/chatbotx-voice-api.js` — HTTP-клиент (`checkPolicy`, `optOut`;
   на этапе 1 — `createCall`, `reportResult`), таймаут 3 с.
8. Проверка в `lib/novofon-call-api.js`: экспортируемые `informerCall`,
   `employeeCall` и `scenarioCall` перед JSON-RPC вызывают `checkPolicy`.
   Все пути набора идут через этот модуль: `order-voice-notify.js` (включая
   отложенную очередь), `order-prepayment-voice.js`, `order-status16-voice.js`,
   `order-status22-voice.js` и через них тестовый вебхук и ручные скрипты.
   `canCall: false` → `{ skipped: true, reason }`, набора нет.
   Недоступность → ошибка `VoicePolicyUnavailableError`; `notifyByOrder` ловит
   её и откладывает звонок (§7).
9. Агент на звонке: при просьбе не звонить — `optOut` и комментарий в заказ.
10. Выключатель `VOICE_AI_POLICY_CHECK=enforce|off` (по умолчанию `enforce`):
    `off` возвращает старое поведение без обращения к ChatbotX — это и есть
    откат.
11. **Тест-режим**: `VOICE_AI_PRODUCTION_ENABLED` остаётся `false`, звонки идут
    только на `VOICE_AI_TEST_PHONES`. Проверка запрета при этом работает
    **по-настоящему**.

Деплой бота делает владелец: `lib` бота подключён симлинком в
`/GKamion/chat-bot/lib` и смонтирован в n8n как `/geka-lib`. Код n8n работает
в Docker-сети `n8n_default`, поэтому ходит в ChatbotX по
`https://chatbotx.gkamion.ru`. Токен `voiceAgent` кладётся в `/opt/n8n/.env` и в
env `voice-ai` — это секреты.

Критерий выхода: на тестовом номере запрет ставится из трёх источников
(реплика, чат, тумблер); после этого бот не звонит ни из очереди, ни из
отложенной очереди, ни с тестового вебхука; заметка на месте; при остановленном
ChatbotX звонок откладывается, а не выполняется.

### Этап 1 — зеркало звонков в карточку

Вводится `VoiceCall`. Бот после `checkPolicy` вызывает `createCall`, после
разговора — `reportResult` (рядом с записью комментария в заказ в
`voice-order-comment.js`). Карточка в диалоге + история в контакте.
`setAiCallOptOut` начинает гасить `queued`/`leased`.

### Этап 2 — перенос планировщика

**Предусловие:** ChatbotX должен знать числовой статус заказа.
`ExternalOrder.status` сейчас — текстовая метка («Current order status label
from GKamion»), а бот работает с id 13/16/22 и вычисляет статус заказа по
позициям (`resolveOrderStatusId`: при смешанных статусах позиций — пропуск).
Нужно передавать `statusId` в событии заказа (или вычисленный статус заказа)
либо завести таблицу соответствия меток и id. Без этого планировать звонки в
ChatbotX нельзя.

`VoiceCall` становится очередью. Переезжают из `order-voice-notify.js` в
ChatbotX:

- окно 09:00–22:00 — вместе с таблицей DEF → TZ (`client-call-window.js`);
  сначала `Contact.timezone`, если задан, потом DEF, потом `Europe/Moscow`;
- дедуп по `(phone, scenario, окно)`;
- лимит параллельных;
- отложенные повторы (`voice_call_deferred.json` → `scheduledFor` в `VoiceCall`);
- `nextCall` + `markDialing` + свипер.

`voice_call_deferred.json` выводится из работы: его строки одноразово
импортируются в `VoiceCall`, файл переименовывается в `.retired`.

### Этап 3 — UI целиком

Страница настроек, фильтр в аудиториях рассылок.

## 11. Риски и ограничения

1. **Лицензии TTS — блокер будущего запуска.** В `voice-ai/README.md`
   записано: Silero v5_ru — CC BY-NC 4.0 (некоммерческая), Piper — GPL-3.0,
   RHVoice — GPL. Там же прямо сказано, что для звонков клиентам нужна
   коммерческая лицензия. Пока это внутренний инструмент GKamion — вопрос
   открытый. Как только голосовой бот станет **фичей ChatbotX для других
   workspace**, лицензионный долг становится блокером запуска. Варианты:
   коммерческая лицензия Silero, Yandex SpeechKit (код у бота уже готов,
   `voice-tts-provider.sh yandex`), собственный TTS. Решение — до этапа 3.
2. **Транскрипт — ПДн.** Политика уже сформулирована для
   WhatsApp-звонков (`whatsapp-calling-voip.md`, R26): полный текст хранится и
   отдаётся вебхуком. Для звонков робота то же самое; `transcript` не
   логируется и не попадает в `error-log`.
3. **Запись разговора требует предупреждения** в начале. У бота этого сейчас
   нет. Отдельная задача, не входит в эту спеку.
4. **Детектор чата — эвристика.** Ложные срабатывания будут. Поэтому: только
   повелительные формы с границами слов, отрицательный фильтр, цитата в
   заметке, снятие менеджером.
5. **Fail closed останавливает звонки при сбое ChatbotX.** Сознательный
   компромисс: пока ChatbotX недоступен, звонки GKamion откладываются. Аварийный
   выход — `VOICE_AI_POLICY_CHECK=off` у бота.
6. **Окно 09–22 переносится в ChatbotX** — это ~300 строк табличных данных,
   их легко рассинхронизировать с ботом. После этапа 2 источник один —
   ChatbotX; бот свой `client-call-window.js` больше не вызывает.

## 12. Тесты

- `resolveVoiceCallPolicy` — таблица: флаг/нет × ноль/один/несколько
  контактов с номером × флаг на другом контакте того же номера × blocked/нет ×
  невалидный номер, включая fail-closed (мок, бросающий ошибку БД) и чтение
  мимо кэша.
- `detectOptOutRequest` — положительные фразы; отрицательные: «курьер не
  звонит», «мне никто не звонил», «не звоните, я сам приеду», «перезвоните
  мне», «почему вы не звоните мне»; мусор, пустая строка.
- `setAiCallOptOut`: второй вызов не перезаписывает `source` и не дублирует
  заметку; флаг ставится на все контакты с номером; неизвестный номер создаёт
  контакт; контакт без телефона получает заметку с предупреждением.
- `clearAiCallOptOut` снимает флаг со всех контактов с номером.
- Этап 1: `createCall` идемпотентен по `externalSessionId`; неоднозначный номер
  не вызывает `syncCustomer`.
- Этап 1: пурж `queued`/`leased` при установке флага.
- Этап 2: два параллельных `nextCall` → разные `callId`; второй звонок на тот
  же номер не выдаётся, пока первый живой; `markDialing` на `suppressed` →
  `409`; истёкший лизинг → `queued`, 3 истечения → `failed`; `dialing` старше
  2 часов → `failed`, не `queued`.
- Бот: при `canCall: false` JSON-RPC вызов не делается ни для одной из трёх
  функций; при таймауте `notifyByOrder` откладывает звонок; при
  `VOICE_AI_POLICY_CHECK=off` ChatbotX не вызывается.
- Фильтр: `aiCallOptOut` = true/false, включая NULL-строки (трёхзначная логика).
- Скоуп: токен `["contacts"]` получает 403 на `/v1/voice-agent/*`; `read_only`
  получает 403 на `optOut`.

## 13. Decision Log

| Решение | Рассматривали | Выбрали | Почему |
|---|---|---|---|
| Кто решает «звонить сейчас» | n8n остаётся оркестратором; только флаг + карточка; полный перенос в worker | **ChatbotX планирует, бот исполняет** | Все гейты (окно, дедуп, лимит, согласие) в одном месте, видимом в UI, а не в `.env` на VPS |
| Что гасит отказ | только ИИ-диалоги; все звонки бота; все звонки вообще; два флага | **Все автоматические звонки бота, включая `informerCall`** | Для клиента робот-оповещение — тоже звонок робота; живой менеджер звонить может |
| Как ставится флаг | только бот; только менеджер; авто + менеджер; авто без тумблера | **Авто (звонок + чат) + ручной тумблер** | Авто — основной путь, тумблер — резерв, когда детектор не сработал |
| Где проверяется флаг | на одном контакте; по номеру | **Флаг на контакте, проверка по всем контактам с номером** | Звонят на номер, а контактов с одним номером несколько — по одному на канал |
| Транспорт | push из ChatbotX; через n8n; гибрид | **Pull: бот обращается к ChatbotX** | Проще: ChatbotX не нужно знать адрес бота и следить за его доступностью; откат — один выключатель у бота |
| Где проверка у бота | в каждом сценарии; в gateway | **В `novofon-call-api.js`** | Единственный модуль, через который идёт любой набор, включая отложенную очередь и тестовый вебхук |
| Неизвестный номер | не звонить; звонить без контакта | **Звонить; контакт создаётся при записи звонка или опт-ауте** | Иначе отвалится часть текущих звонков; проверка остаётся чистым чтением |
| Просьба во время звонка | положить трубку сразу; договорить + менеджер | **Договорить штатно** | Не рвём трубку живому человеку из-за одной фразы |
| Порядок | сразу всё; только флаг навсегда | **По этапам, старт в тест-режиме** | Этап 0 обратим выключателем; планировщик — самый рискованный шаг, он последний |
| Модель флага | boolean + дата; таймстемп | **Таймстемп** | Как `blockedAt`/`broadcastSubscribedAt`; даёт `buildBooleanFromTimestamp` бесплатно |
| Скоуп API | `ecommerce`; новый `voiceAgent` | **Новый `voiceAgent`** | Токен управляет звонками, а не читает каталог; принцип наименьших прав |
| Статус «не позвонили» | просто `canceled`; отдельный статус | **`suppressed` + `suppressedReason`** | Иначе менеджер не отличит «ещё не дошло» от «клиент запретил» |
| Лизинг на время разговора | продлевать heartbeat'ом; снимать при наборе | **Снимать при `markDialing`** | Лизинг нужен только до набора; после набора повтор недопустим, зависшие звонки уходят в `failed` |
| Fail при недоступной проверке | звонить; не звонить; откладывать | **Не звонить, откладывать звонок** | Молчание дешевле звонка тому, кто просил не звонить, но звонок по заказу не теряется |
