# T05 — сервис покрытия и восстановления памяти диалога

## Статус и состав

Исходный код частей A (покрытие) и B (сервис) принят независимыми проверками соответствия требованиям и качества. Часть C добавляет публичные экспорты и этот документ. Функция **не включена в рабочей системе**.

- `packages/business/src/external-agent/memory-coverage.ts`: хеши содержимого, сравнение манифеста, кодирование и проверка хранимой записи.
- `memory-service.ts`: фабрика `createDialogMemoryService` и ограниченный по ресурсам сервис восстановления.
- `memory-service-types.ts`: только типы портов, ограничений и результатов.
- `index.ts`: сохранены шесть прежних экспортов, добавлены экспорты двух модулей и именованный `export type` публичных типов.

Корневой `packages/business/src/index.ts` уже экспортирует `./external-agent`. Его и `package.json` не меняли. Новые экспорты не вызывают фабрику и не создают соединений с БД. Типовой экспорт стирается при преобразовании TypeScript; существующие зависимости прежних модулей остаются.

## Интерфейс

`createDialogMemoryService({ repository, summarizer, validator, config })` требует все три порта. Готовых подмен генератора или всегда принимающего валидатора нет.

Конфигурация: `{ scope, config, validatorVersion, deadlineAtMs, nowMs?, budgets? }`.

- `scope`: workspaceId, conversationId, expectedContactId — строковые идентификаторы.
- Вложенный `config`: schemaVersion, promptVersion, model, provider.
- `deadlineAtMs`: абсолютный предельный момент времени в миллисекундах; `nowMs` по умолчанию использует `Date.now`.
- `validatorVersion`: непустая серверная метка совместимости проверки.
- `budgets`: при необходимости более строгие ограничения, чем значения по умолчанию.

Фабрика проверяет параметры и методы портов до обращения к ним, копирует конфигурацию. Некорректные параметры вызывают исключение.

Методы:

- `getTrustedContext({ signal? })` возвращает `DialogMemoryContextResult`.
- `reset({ expectedToken })` передаёт явный CAS-токен в `resetDerived` для закреплённого диалога. Автоматического сброса при ошибках генерации нет.

Идентификаторы не преобразуются в JS number. Время исходных сообщений сохраняет шесть знаков микросекунд UTC. Токен версии содержит `sourceRevision`, `memoryVersion`, `topologyEpoch`.

## Подготовка контекста

1. Зарегистрировать диалог через репозиторий. Полностью прочитать страницы истории с одним токеном версий и последовательно выдаваемыми курсорами. Проверить принадлежность сообщений и вложений, порядок, отсутствие повторов и полноту прохода.
2. После завершения всего прохода развернуть **всю** накопленную последовательность DESC в ASC. Неполный проход не считается полной историей.
3. Проверить хранимую запись, её версии, владельца, конфигурацию и манифест. Неизменный покрытый префикс разрешает дополнение. Правка, удаление или поздняя вставка внутри него требуют восстановления; прежняя сводка не передаётся даже с пометкой «устарела».
4. Сначала измерить весь ответ. Если проверенная сводка и весь необработанный остаток помещаются, вернуть их без вызова модели. При восстановлении таким ответом может быть вся исходная история без сводки.
5. Только при переполнении выбрать старейшую непрерывную пачку, получить кандидата и проверить его семантическим валидатором. Сервер сам назначает охват, манифест и служебные параметры.
6. До ожидания публикации закодировать принятую запись и получить независимую копию. Опубликовать с проверкой трёх версий. Конфликт требует нового полного прохода, а не подстановки свежего токена к прежним данным. Продолжение частичной сводки также использует новый проход и новый токен.

Переданные портам данные копируются. Последующее изменение объекта валидатором не меняет сохранённый или возвращённый результат. Проверено отдельными синтетическими сценариями.

## Границы ответственности

- Покрытие сводкой **не означает доставку Hermes**. Текущий ещё не принятый пакет сообщений сохраняется отдельно; объединение с исходным остатком выполняет T10.
- Сервис не меняет самостоятельно счётчик исходной переписки, маркеры запуска, идемпотентности или доставки. Регистрация и публикация выполняются только через репозиторий.
- Фильтрация недопустимых для передачи внутренних комментариев относится к политике T07/T10, а не к вычислению хешей источников.
- Сводка не подтверждает оплату, актуальный статус заказа или полномочия клиента. Эти проверки остаются вне неё.
- Ошибки репозитория (`not_found`, `unsupported` и другие) сохраняют собственные варианты результата, а не превращаются в пустую историю. Внутренние ошибки сервиса, отмена и превышение ограничений дают `context_unavailable` с постоянной причиной.
- При ошибке генерации, отклонении кандидата или конфликте прежняя контрольная точка не удаляется. Молчаливого усечения истории нет.
- Отмена останавливает ожидание и дальнейшие шаги сервиса. Уже начатая транзакция публикации T04 может завершиться после отмены ожидания; отмена её фиксации не гарантируется.

## Ограничения ресурсов

Значения по умолчанию одновременно служат верхними пределами фабрики; разрешены меньшие положительные безопасные целые значения.

| Параметр | Значение | Область |
|---|---|---|
| pageSize | 100 | одна страница; текущий максимум сервиса — 100, хотя T04 допускает 200 |
| maxPageFetches | 200 | весь запрос, включая повторные проходы |
| maxCycles | 2 | весь запрос |
| maxLlmCalls | 2 | весь запрос |
| maxScanItems | 20 000 | один полный проход |
| maxScanLogicalBytes | 16 MiB UTF-8 | один проход; общие счётчики работы накапливаются |
| maxBatchItems | 100 | одна пачка |
| maxBatchEncodedChars | 24 000 | одна пачка |
| maxOutputEncodedChars | 20 000 | весь JSON-ответ, включая сводку, исходный остаток и метаданные |
| maxStoredJsonBytes | 8 MiB UTF-8 | вся хранимая запись |

Это ограничения работы, а не обещание вместить произвольную историю. Превышение приводит к явному отказу, не к потере начала переписки.

## Последующие этапы и проверка

T07 должен предоставить настоящий семантический валидатор, T09 — клиент модели, T10 — сборку конечного входа и политику допуска источников. T09 обязан ограничивать **весь сериализованный запрос к модели**: нельзя слепо включать полный старый префикс в дополнение к сводке и новой пачке. Для инкрементального запроса используются прежняя проверенная полезная нагрузка, новая пачка и необходимые цитаты в пределах бюджета. Полный `sourceEvidence` для детерминированной проверки T07 — отдельный набор, не автоматически весь текст промпта.

Части A/B проверены непосредственным запуском модулей на синтетических DTO и портах, а также точечным анализом Biome. Для C фактически выполнены семь статических проверок экспортов и синтаксического преобразования без исполнения общего модуля business и его зависимостей от БД. Эти проверки не заменяют компиляцию пакета.

Для текущего T05 не выполнялись полный Vitest, общая проверка типов, сборка, испытания на БД, CI, миграции и настоящая интеграция с моделью. Все они остаются условиями выпуска. Применение миграции и включение функции требуют отдельного разрешения.
