# Синтетические сценарии памяти диалога

Единственный исполняемый набор — `cases.v2.json`. `cases.v2.schema.json` — его JSON Schema Draft 2020-12, не второй набор. Не загружайте все JSON-файлы каталога как сценарии.

Статус: машинный кандидат, `humanApproved: false`; 30 случаев, 20 development и 10 holdout. Это не реальные переписки и не подтверждённые данные CRM. Числовые иллюстрации адаптированы из обсуждения, сообщения синтетические; результаты сравнения моделей отсутствуют. Человеческая проверка критических меток и проверка оценщика ещё не пройдены.

`currentMessageIds` — окно текущего запроса, не граница доступной истории. Для допустимых свидетельств используется вся разрешённая история после изменений, кроме удалённых сообщений. Исторические сообщения не доказывают текущее состояние ERP.

Оценочные поля requiredEvidence/forbiddenClaims/openQuestions/expectedBehavior и mutation не передаются суммаризатору. Адаптер формирует вход модели по явному списку разрешённых полей. Отложенные ответы не используются для настройки промпта. Случаи без вызова модели и проверки маршрутизации не повышают показатели качества пересказа.

Ключи сообщений непрозрачные, не идентификаторы PostgreSQL. Нужна отдельная взаимно обратная таблица с синтетическими каноническими DTO id. Сохраняются буквальные цитаты, строки сумм/идентификаторов и точность времени.

Правила и ограничения: `docs/dialog-memory/T06-fixtures.md`. Исходный набор v1 и воспроизводящий скрипт сохранены отдельно в локальном плане. Содержимое v2 проверено JSON Schema и проверками связности: ссылки, цитаты, роли, заказы, удаления, неизменность исходных сообщений и всех отложенных случаев. Это не семантическая оценка модели.
